У вас нет такого опыта? Вы можете связать свой опыт с курсовой работой или

аналитические возможности вашей команды.

прогнозирования (с использованием случайного леса, KNN и деревьев 
решений). Мой подход заключался в том, чтобы свести определение к легко 
понятным описаниям из предложений для каждого алгоритма. Затем я 
создал короткую презентацию со слайдами, чтобы рассказать команде о

 Например:

## Назовите мне случай, когда ваши коллеги не согласились с вашим подходом. Что вы сделали, чтобы решить их проблемы?
Когда интервьюеры задают этот вопрос, они хотят убедиться, что вы можете

## В чем разница между DELETE и TRUNCATE?
 Обе эти команды удалят данные. Однако ключевое отличие состоит в том, 
что DELETE - это команда языка манипулирования базами данных (DML), а 
TRUNCATE - команда языка определения данных (DDL).
 Таким образом, DELETE используется для удаления определенных данных из 
таблицы, а TRUNCATE удаляет все строки таблицы без сохранения структуры 
таблицы. Еще одно отличие: DELETE можно использовать с предложением 
WHERE, а TRUNCATE - нет. В этом случае команда DELETE TABLE удалит все 
данные из таблицы, сохранив структуру, а команда TRUNCATE TABLE 
полностью удалит таблицу.

## В чем разница между WHERE and HAVING?
 
WHERE and HAVING используются для фильтрации таблицы в соответствии с 
заданными вами условиями. Разница между ними очевидна при 
использовании в сочетании с предложением GROUP BY. Предложение 
WHERE фильтрует строки перед группировкой (перед предложением GROUP 
BY), а HAVING используется для фильтрации строк после сбора.

## Что такое индекс в SQL? Когда вы будете использовать индекс?
 Индексы — это справочные таблицы, используемые базой данных для более 
эффективного поиска данных. Пользователи могут использовать индекс для 
ускорения выполнения предложений SELECT или WHERE, но они замедляют 
выполнение операторов UPDATE и INSERT.

## Что такое агрегатные функции в SQL?
 Агрегатная функция выполняет вычисления над набором значений и 
возвращает одно значение, суммирующее фон. Три наиболее 
распространенные агрегатные функции SQL - это COUNT, SUM и AVG.
 COUNT - возвращает количество элементов группы. SUM - возвращает 
сумму ALL или DISTINCT значений в выражении. AVG - возвращает среднее 
значение значений в группе (и игнорирует значения NULL).

## Какие команды SQL используются в ETL?
 Некоторые из наиболее распространенных функций SQL, используемых в 
процессе извлечения данных, включают SELECT, JOIN, WHERE, ORDER BY и 
GROUP BY.

 SELECT - эта функция позволяет нам получить нужные данные.

 JOIN - используется для выбора столбцов из нескольких таблиц с 
использованием внешнего ключа.

 WHERE - мы используем, где указать, какие данные нам нужны.

 ORDER BY - позволяет нам организовать столбец в порядке возрастания или 
убывания.

 GROUP BY - эта функция группирует результаты нашего запроса.

## Влияет ли порядок JOIN на производительность SQL - запросов?
 Способ объединения таблиц может существенно повлиять на 
производительность запросов. Например, если вы JOIN большие таблицы, а
затем JOIN меньшие таблицы, вы можете увеличить объем обработки, 
необходимой механизму SQL. Одно общее правило: объединение двух 
таблиц, которое уменьшит количество обрабатываемых строк на 
последующих шагах, поможет повысить производительность.

## Вам даны таблица пользователей и таблица соседей. Напишите запрос, который возвращает все районы с 0 пользователями.
 Всякий раз, когда задается вопрос о поиске «0 значений», например, 
пользователей или окрестностей, начинайте думать LEFT JOIN! Внутреннее 
соединение находит любые значения в обеих таблицах; LEFT JOIN сохраняет 
только значения в левой таблице.

 В этом вопросе наша затруднительное положение состоит в том, чтобы найти 
все районы без пользователей. Для этого мы должны выполнить левое 
соединение таблицы соседей с таблицей пользователя. Вот пример решения:

    SELECT n.name
    FROM neighborhoods AS n
    LEFT JOIN users AS u
    ON n.id = u.neighborhood_id
    WHERE u.id IS NULL

## Bonus Question: Почему нам следует использовать суррогатные ключи вместо обычных ключей?
Суррогатные ключи — это генерируемые системой уникальные ключи для 
записи в базе данных. Они предлагают несколько преимуществ по 
сравнению с обычными или естественными ключами:

 Согласованность: суррогатные ключи обычно имеют одинаковый формат и 
часто представляют собой целые числа с автоматическим приращением.

 Неизменность: поскольку они генерируются системой, они не подвержены 
такому же риску изменения, как естественные ключи, которые могут быть 
основаны на изменяемых данных.

 Анонимность. Обычно их нельзя использовать для определения 
характеристик реального мира, что полезно для обеспечения 
конфиденциальности данных.

 Совместимость. Они могут устранить разрыв в сценариях, в которых 
естественные ключи из разных систем или контекстов несовместимы.

 Производительность. Суррогатные ключи на основе целых чисел могут быть 
более эффективными для выполнения запросов по сравнению с более 
длинными естественными ключами на основе строк.

 Важно отметить, что, хотя суррогатные ключи имеют свои преимущества, их 
следует использовать разумно, а решение должно основываться на 
конкретных требованиях конструкции базы данных./////
